# HTTP 与链路压测核心自动化增量

2026-10-11。对应 WhaleTestPro `5f4f53a`。本仓仅新增核心自动化，不宣称全量接口/协议覆盖。所有 P 级均是建议值，需人工确认；新 `PERF-*` 编号是本增量的独立编号，不冒充原 `WTP-API-*` Excel 编号。

## 资料和设计依据

- `WhaleTestPro/docs/Locust接口与链路压测.md`：HTTP 请求体、链路、变量、失败断路、统计和隔离约束。
- `WhaleTestPro/app/schemas/perf_plan.py`：single/chain、1–100 步、请求体类型、相对路径、JSONPath、Schema 本地引用等限制。
- `WhaleTestPro/app/schemas/perf.py`：可空 load_config、iteration_stats 及 Host 限制。
- `WhaleTestPro/app/routers/perf.py`、`app/services/perf.py`：删除 409/503/404 及保留记录、所属租约的语义。

按 `testcase-design` 的等价类、边界、状态转换和横切维度梳理。配置设计在 `common/perf_cases.py::config_cases()`，每条返回独立的九字段记录（模块、测试点、编号、标题、建议优先级、来源、前置、步骤、预期）及完整 request；不会用“同上”省略字段。

配置共 20 条：P001–P005 为 JSON/链路/form/raw/HEAD 正向；B001–B002 为链路 1/100 步；N001–N013 为 0/101 步、single 多步、TRACE、错误 body、绝对路径、CRLF、非法提取、远程 Schema、带凭证/Query 的 Host。统一断言 201 保存并读回，或 422 字段错误且任务 ID 集合不变。

## 验证层与运行

- `testcases/test_perf_core/test_perf_core.py`：27 个 HTTP 参数化实例（20 配置 + 7 异步），不导入后端代码。
- `tests/test_perf_core_contract.py`：配置/删除经真实 HTTP 路由、权限解析及隔离 SQLite；身份、Redis、消息发布受控。运行脚本经真实迭代引擎及纯模拟目标函数验证，Worker 调度、网络传输和控制采样是替身，不冒充真实链路验收。
- 错误统计为0轮、无请求行、错误方法、链路缺步骤、失败后继续请求时，自动化必须失败；这些防误判反例另有离线回归。
- `scripts/perf_fixture_server.py`：仅合成数据。订单 ID 从合成 Token 派生，校验 Authorization、JSON 类型、Header 和 Query；不存真实账号或订单，不记录 URL/正文/Token。
- CI 使用原 app 镜像启动独立夹具容器，无宿主端口；有单独的核心门禁且关闭重跑，后续全量步骤排除 perf_core，避免重复执行。

离线：`python -m pytest tests --reruns 0`。没有压测前置服务，不会连接已部署平台。

HTTP 配置：在隔离测试平台设置 `WHALE_PERF_CORE_ALLOW_WRITES=1`，运行 `python -m pytest testcases/test_perf_core -m 'not async_e2e' --reruns 0`。

真实核心：还需配置 `WHALE_PERF_ALLOW_LOAD=1`、`WHALE_PERF_FIXTURE_BASE_URL=http://<Worker可达的专用夹具Host>:8090`，运行 `python -m pytest testcases/test_perf_core --reruns 0 --alluredir=allure-results`。不要指向 WhaleShop，不要在有实际业务资产的共享平台开启这些开关。测试账号无删除接口，只能由隔离测试库生命周期回收。

横切走查：状态时序覆盖pending/queued/running/终态故障及恢复；持久化覆盖创建→详情→列表；一致性覆盖422无新任务、409/503保留记录与租约、吞吐=完成轮次/采样经过时间。故障不通过停止真实 Master 来制造。权限矩阵沿用原套件；高并发多主竞态、数据库宕机、协议/证书/上传扩展和浏览器UI不在本次核心增量范围。
