# 回归与定时任务整合同步（2026-10-18）

用户确认后整合“回归测试”和“定时调度”。当前主仓包含未提交的整合改动及此前压测历史/TPS 功能；两仓本轮均未 commit/push。

## 接口与脚本变更

- 删除 `POST /regression`，平台操作数从 108 降为 **107**。改用 `GET /regression/options`、`POST /regression/preview`、`POST /regression/run`。预览不执行，运行须携带当前 `preview_key`。
- 新选择为 `mode`、非空 `ids`、可选 `env_id`；空选择 422，不再返回旧 `no_tests`；结果含 `report_id`，根结果项使用 `id`/`name`。选择和配置变化保护继续验证。
- `common/core_flow.py` 新增 `run_selected_cases`，核心 4 项回归场景及历史 `test_misc` 调用迁移到两步执行。执行权限矩阵从 owner 获取只读预览，再向被测角色提交运行请求，确保 outsider 测的是实际运行入口的权限拒绝。
- 定时任务五项 CRUD 路由保留，新增 `selection={mode,ids}` 与 `notify`；与旧标签/套件筛选互斥。旧任务在后台保留规则，新 UI 编辑保存后改为明确选择。
- 新增 `testcases/test_core/test_scheduled_regression.py` 的 7 项 HTTP 场景：case/suite 两种保存与启停回显、三种非法选择、跨项目目标拒绝，以及旧入口移除且无执行。对应离线入口为 `tests/test_scheduled_regression_contract.py`。
- 核心离线 fixture 注册 schedule 路由，以受控调度替身代替 Redis 写入；实际 HTTP 用例会验证真实同步状态。没有在普通 HTTP 测试中导入后端代码或直接派发 Worker。
